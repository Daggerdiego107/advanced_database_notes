## What I understood
- A KPI is only trustworthy when the contract is explicit: definition, filters, unit, and edge cases all have to be stated before the query.
- Starting from a dimension table like `teams` and using `LEFT JOIN` keeps empty groups visible, which is important for dashboard reporting.
- Some metrics become misleading when they mix unrelated values, so it helps to separate completed work, active work, cancelled work, and overdue work.
- Oracle offers useful tools for these exercises, especially `PERCENTILE_CONT`, `TRUNC(SYSDATE)`, and interval arithmetic for resolution time calculations.

## What is still confusing
- The exact Oracle arithmetic rules when subtracting `DATE` and `TIMESTAMP` values, especially when converting differences into hours.
- When a dashboard should use an average, a median, or a summary row to avoid hiding the real shape of the data.
- How to choose SLA thresholds and urgency weights so the metric stays useful instead of becoming arbitrary.

## Questions
